# 역할 — 장치 조립 → 대안 스토리라인 + 자가진단

입력으로 앞 단계가 쿼리별로 완성한 연출 장치 목록이 주어진다(각 장치는 이미 실제 레퍼런스
근거를 가지고 있다). 이 장치들을 조합해 최종 문서를 완성한다 — 형식은
`generation/docs/DBH_Creative_Reference_Ideas.md` 와 동일한 사고 과정을 따른다: 대안
스토리라인 여러 안 → 비교·권고 → 공통 체크 → 다음 단계. 그리고 마지막에 지금 가진 장치만으로
충분한지 스스로 진단한다.

## 1) 대안 스토리라인 (`storylines[]`, 3~4안)
장치들을 조합해 {{ad_length}} 분량의 완결된 스토리라인 대안을 만든다. 서로 다른 장치 조합·
다른 서사 축을 써서 안끼리 실제로 달라야 한다(전부 같은 장치를 우려먹지 마라). 각 안:
- `label`("안 A — <이 안의 핵심을 요약한 짧은 이름>" 형식), `one_liner`(핵심을 한 문장으로),
  `devices_used`(사용한 장치 이름들 — 입력받은 장치의 `name`을 그대로 인용)
- `structure[]`: 시간 구간별 전개(`time_range`·`content`·`device_tags`) — {{ad_length}} 전체를
  빠짐없이 커버.
- `strengths`/`weaknesses`/`difficulty`: 이 안의 강점·약점·제작 난도를 솔직하게. **각 필드는
  배열이 아니라 하나의 문자열**로 써라(여러 포인트가 있으면 한 문장/문단 안에 자연스럽게
  녹여라 — `["강점1", "강점2"]` 같은 리스트 형식 금지).

## 2) 비교와 권고 (`comparison[]`, `recommendation`)
`comparison[]`은 `storylines[]`와 **정확히 같은 개수, 같은 순서**로 채운다. 각 행의 `label`에는
그 스토리라인의 `label`을 **그대로(글자 하나 바꾸지 않고) 복사**해서 채워라 — 절대 빈 문자열로
남기지 마라. `impact`/`concept_fit`는 그 스토리라인 내용을 근거로 다시 평가해 채운다(storylines
의 서술과 모순되지 않게). **`impact`/`concept_fit`는 반드시 1~5 사이의 순수 정수만 써라**
(`"high — 이유..."` 처럼 설명을 섞은 문자열 금지 — 이유를 쓰고 싶으면 `difficulty`나 다른
서술 필드에 써라). `difficulty`는 문자열로 low/mid/high 를 쓴다.

하나를 권고하거나 여러 안의 장점을 조합한 하이브리드를 권고하라. `recommendation`은
**`{"choice": "...", "rationale": "..."}` 형식의 객체**로 채워라(문자열 하나로 뭉뚱그리지 마라)
— `choice`에 권고하는 안(라벨 또는 하이브리드 구성), `rationale`에 왜 그 선택인지 근거를 적는다.

## 3) 공통 체크 (`common_checks[]`)
어느 안을 택하든 지켜야 할 제약 — 입력된 제품 맥락(리스크·클레임·규제 소지·제품 노출 시점 등)에서
실제로 도출하라. 일반론("좋은 광고를 만들자") 금지, 이 제품·이 원칙에 특정된 체크만.

## 4) 다음 단계 (`next_steps[]`)
스토리라인 선택 → 콘티 작성 → 소스 계획 순으로, 이 프로젝트 상황에 맞게 2~4개.

## 5) 자가진단 (`gap_assessment`)
방금 만든 스토리라인들을 다시 냉정하게 보라. 장치가 부족해서(예: 특정 축의 근거가 아예 없거나,
레퍼런스 미발견 장치뿐이거나, 안들이 서로 다른 그림을 못 그리고 비슷해지는 경우) 스토리라인이
설득력이 약하다고 판단되면:
- `sufficient`: `false`
- `note`: 정확히 무엇이 부족한지 1~2문장(예: "톤·무드 축 레퍼런스가 전무해 안들의 첫인상이
  전부 추상적으로만 서술됨").
- `additional_queries[]`: 그 공백을 메울 추가 검색 쿼리 1~3개. 형식은 앞서 받은 쿼리와 동일하게
  `axis`/`label`/`rationale`/`query_text`/`target_collection`을 채우되, **이미 쓴 쿼리와
  겹치지 않는 새로운 각도**여야 한다.

충분하다고 판단되면 `sufficient: true`, `note: ""`, `additional_queries: []`로 남겨라. 추가
검색은 비용이 드는 작업이니, 정말 스토리라인의 설득력이 떨어질 때만 요청하라 — 이미 충분한데도
습관적으로 더 찾지 마라.

# 출력
JSON 객체 하나만(`storylines`, `comparison`, `recommendation`, `common_checks`, `next_steps`,
`gap_assessment` 키 모두 포함). 코드펜스·설명·머리말 없이.
