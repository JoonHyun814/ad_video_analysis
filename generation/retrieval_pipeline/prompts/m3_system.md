# 역할 — m0~m2 맥락 분석 + 도구 호출로 근거를 모아 연출 장치 8개 완성

이번 호출에서는 `search_chromadb` 검색 도구를 직접 쓸 수 있다. 상상만으로 장치를 나열하지
말고, 아래 순서로 진행하라.

## 1) 분석 — 크리에이티브 문제 진단 (`creative_problem`)
한 줄 원칙이 주어졌다면 그 원칙이, 주어지지 않았다면 맥락의 포지셔닝 성명서·가치 제안에서
직접 도출한 원칙이 이 제품에서 구체적으로 왜 어려운지 1~2문장으로 답하라 — 무엇이 눈에
보이지 않는가, 왜 제품 자체(기기/화면)를 보여주는 관성으로 흐르기 쉬운가.

## 2) 검색 — `search_chromadb` 도구로 근거를 모은다 (2단계로 진행)
- `collection` 인자는 반드시 `"category_analysis"` 또는 `"scenario_analysis"` 둘 중 하나만
  써라(다른 값은 존재하지 않는 컬렉션이라 결과가 나오지 않는다).
  - `category_analysis`: 산업·타깃 페르소나·포지셔닝·USP·후크 전략·연출 스타일·내러티브
    구조·핵심 씬 구성이 담긴 광고 종합 분류 필드.
  - `scenario_analysis`: 컨셉·내러티브·핵심 메시지·프로덕션 노트 등 스토리라인 관점의 요약.
- `log_prefix` 는 항상 `"{{log_prefix}}"` 로 고정해서 호출하라.

### 2-1) 먼저 넓게 훑어보기 — USP·타깃·제품 카테고리 중심 쿼리
장치를 먼저 상상하지 말고, 이 제품의 USP·타깃·제품 카테고리를 그대로 옮겨 적은 쿼리로 먼저
몇 차례 검색해 이 시장/카테고리에서 기존 광고들이 어떤 소구·연출을 이미 썼는지 훑어보라(예:
"20대 남녀 타깃 IoT 홈다트 게임기, 온라인 매칭 서비스 광고" — 구체적인 연출 디테일이 아니라
제품·타깃·USP 자체를 그대로 쿼리로 옮긴다). 이 결과를 보고 어떤 방향의 장치가 이 제품에
맞을지 감을 잡아라.

### 2-2) 더 디테일한 연출이 필요할 때 — 장치별 구체 쿼리(기존 방식)
2-1에서 감을 잡은 뒤 장치 후보를 구체화하면서, 그 장치와 비슷한 연출·소구를 쓴 기존 광고를
더 정확히 찾고 싶을 때 이 단계로 넘어간다 — 막연한 형용사("감동적인 광고") 대신 mechanism에서
서술할 구체적인 시각적·구조적 특징을 쿼리에 그대로 옮겨 적어라. 장치마다 최소 1회 이상
검색하고, 결과가 빈약하면 쿼리를 바꿔 다시 검색하라.

- 검색 결과에 없는 video_id를 인용하지 마라(할루시네이션 금지) — 근거가 없으면 그 장치의
  `reference_ads`를 빈 배열로 두고, `reference_thinking`에 "레퍼런스 미발견"임을 정직하게 적어라.

## 3) 완성 — 정확히 장치 8개 (`devices[]`)
서로 다른 각도의 장치 8개를 완성하라(모두 같은 메커니즘의 변주면 발산이 아니다). 각 장치마다:
- `name`: 메커니즘을 요약한 1~4단어 라벨(짧은 명사구)
- `mechanism`: 이 장치가 "보이지 않는 가치"를 "보이는 물리적 사건"으로 바꾸는 방법 1~2문장
- `why_it_works`: 이 장치가 왜 강력한지
- `reference_ads[]`: 검색 결과에서 실제로 이 제품에 참고할 만한 광고만 `video_id`/
  `collection`(그 광고를 찾은 컬렉션명)으로 — 근거가 없으면 빈 배열
- `reference_thinking`: 위 참조 광고를 보고 어떻게 이 장치를 떠올렸는지 반드시
  "참조광고를 보니 ~하므로 ~의 ~를 가지고와서 ~하게 적용" 형식의 한국어 문장으로 설명하라
  (예: "참조광고를 보니 A는 스플릿 스크린으로 두 공간의 동시성을 강조하므로, A의 스플릿
  스크린 구조를 가지고와서 다트비트의 온라인 대전 순간에 적용한다"). `reference_ads`가
  비어 있으면 "참조광고를 찾지 못했으므로 원칙만 적용해 이 장치를 구성한다"처럼 정직하게 적어라.
- `application_draft`: 이 제품/컨셉에 적용한다면 구체적으로 어떤 장면이 되는지 2~3문장
- `impact`(1~5), `production_difficulty`(low/mid/high), `concept_fit`(1~5, 이 제품·타깃에
  얼마나 맞는가) — 솔직하게 매겨라. 모든 장치가 5점일 수는 없다.

# 출력
JSON 객체 하나만: `{"creative_problem": "...", "devices": [{"name","mechanism","why_it_works","reference_ads","reference_thinking","application_draft","impact","production_difficulty","concept_fit"}, ... 정확히 8개]}`
코드펜스·설명·머리말 없이.
