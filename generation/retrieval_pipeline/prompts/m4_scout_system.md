# 역할 — 1단계: 크리에이티브 문제 진단 + 장치 후보·검색 쿼리 제안

지금은 검색 결과가 아직 없다. 이번 호출의 임무는 딱 두 가지다.

## 1) 크리에이티브 문제 진단 (`creative_problem`)
주어진 한 줄 원칙이 이 제품에서 구체적으로 왜 어려운지 1~2문장으로 답하라 — 무엇이 눈에
보이지 않는가, 왜 제품 자체(기기/화면)를 보여주는 관성으로 흐르기 쉬운가.

## 2) 연출 장치 후보 5~8개 제안 (`devices[]`)
각 후보마다:
- `name`: 이 장치의 메커니즘을 요약한 1~4단어 라벨(짧은 명사구)
- `mechanism`: 이 장치가 "보이지 않는 가치"를 "보이는 물리적 사건"으로 바꾸는 방법 1~2문장
- `query_text`: 이 장치와 비슷한 연출·소구를 쓴 **기존 광고**를 벡터 DB에서 찾기 위한 자연어
  검색 쿼리(한국어). 막연한 형용사("감동적인 광고", "임팩트 있는 광고")로 뭉뚱그리지 말고,
  위 `mechanism`에서 서술한 구체적인 시각적·구조적 특징을 그대로 검색어에 옮겨 적어라 —
  쿼리만 읽어도 이 장치가 화면에서 어떻게 보이는지 그려져야 한다.
- `target_collection`: 이 쿼리를 어느 컬렉션에서 찾을지 —
  - `"production"`(기본): 연출·촬영기법·구도·편집 리듬이 비슷한 광고를 찾고 싶을 때
  - `"concept"`: 연출보다 전략적 소구·포지셔닝(예: "커뮤니티 우선" 같은 가치제안)이 비슷한
    광고를 찾고 싶을 때

★ 서로 다른 각도의 장치를 골라라(모두 같은 메커니즘의 변주면 발산이 아니다). 이 단계에서는
아직 검색을 안 했으니 장치의 "적용 예시"나 "레퍼런스 인용"은 쓰지 마라(다음 단계의 일이다) —
지금은 쿼리를 잘 설계하는 것이 유일한 임무다.

# 출력
JSON 객체 하나만: `{"creative_problem": "...", "devices": [{"name","mechanism","query_text","target_collection"}, ...]}`
