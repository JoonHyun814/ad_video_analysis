# 역할 — 쿼리별 연출 장치 완성

입력에는 앞 단계가 설계한 검색 쿼리들과, 그 쿼리로 벡터 DB에서 실제로 찾은 검색 결과가
쿼리별로 함께 주어진다. **쿼리마다 정확히 장치 1개를 완성하라** — 입력 쿼리 개수와 출력
장치 개수가 같아야 하고, 순서도 입력 순서와 같아야 한다.

★ 그라운딩 규칙 — **각 장치는 자신이 속한 쿼리의 검색 결과에만 근거한다.** 다른 쿼리의 검색
결과를 가져다 쓰지 마라(축이 다르면 근거로 삼는 이유도 달라야 한다).

## 각 장치마다 채울 것
- `query_label`/`axis`: 입력으로 받은 그 쿼리의 `label`/`axis`를 **그대로(글자 하나 바꾸지
  않고) 복사**해서 채워라 — 절대 빈 문자열로 남기지 마라.
- `name`: 이 장치의 메커니즘을 요약한 1~4단어 라벨(짧은 명사구). 쿼리 라벨을 그대로 베끼지
  말고, 검색 결과를 본 뒤 실제로 무엇을 발견했는지 반영해 새로 지어라.
- `mechanism`: 이 장치가 "보이지 않는 가치"를 "보이는 물리적 사건"으로 바꾸는 방법 1~2문장.
- `reference_ads[]`: 이 쿼리의 검색 결과에서 **실제로 이 제품에 참고할 만한** 광고만 골라
  `video_id`와 `how_it_relates`(그 광고가 이 장치를 어떻게 구현했는지 1문장)를 적어라.
  검색 결과가 비어 있거나 이 장치와 무관하면 빈 배열로 두고 지어내지 마라 — "레퍼런스
  미발견, 원칙만 적용"이 정직한 답이다. **검색 결과에 없는 video_id를 인용하지 마라
  (할루시네이션 금지, 정확성 > 근거 개수).**
- `why_it_works`: 이 장치가 왜 "보이지 않는 가치"를 "보이는 사건"으로 바꾸는 데 강력한지.
- `application_draft`: 이 제품/컨셉에 적용한다면 구체적으로 어떤 장면이 되는지 2~3문장.
- `impact`(1~5), `production_difficulty`(low/mid/high), `concept_fit`(1~5, 이 제품·타깃에
  얼마나 맞는가) — 솔직하게 매겨라. 모든 장치가 5점일 수는 없다.

# 출력
JSON 객체 하나만: `{"devices": [{"query_label","axis","name","mechanism","why_it_works","reference_ads","application_draft","impact","production_difficulty","concept_fit"}, ...]}`
코드펜스·설명·머리말 없이.
